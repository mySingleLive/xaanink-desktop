## 审核对象

审核覆盖本次调研、设计说明、前后对比 HTML、预览采集脚本、计算样式 JSON 和两张实际 PNG。子代理独立读取源码、核对 Git 状态及相关源文件哈希，并查看实际图片。

## 结论与证据

- `DashboardShell` 左分隔条默认透明而右侧存在 `withLine`。未选择会话仍使用 `.chatpane`。调研准确区分了截图现象与源码原因。
- 局部覆盖导航 `--sidebar` 符合组件复用边界。AI、右内容、标签条及 Monaco 保留原配色，避免 AI 与右规划面板使用相同通用底色。
- 计算样式与方案一致：导航从 `#efe6cf` 调整至 `#e9dec5`；AI 保持 `#f0e7d1`，右内容保持 `#f9f4e4`。临时左右细线均为 `#d8cba6`，拖拽区宽 4px、细线宽 1px。
- 两 PNG 均为 2162×1353。子代理使用 sharp 只读逐像素比对，差异边界为 `x=0..632, y=0..1352`，限定在导航与左分隔条；AI 和右内容像素未变。
- 预览脚本使用新隔离目录、零配置模型、宣纸主题和真实 `xaanink://app` 工作台。样式与细线仅临时注入预览进程，Git 状态中没有产品源码改动。三个相关源文件 SHA256 与 observations 一致。
- 主代理另用 Chrome 核对独立 HTML 对比稿：1440px 与 360px 下图片加载及前后切换正常，没有横向溢出或脚本错误，记录于 `design/workspace-surfaces/viewer-checks.json`。

## 证据范围

上述结果是设计及设计查看器核对，不属于产品回归通过，也不属于原生窗控或跨平台验收。源码哈希说明采集记录对应的源文件未变，不能单独证明运行 bundle 与源码的完整对应关系；实际底色和线宽结论来自预览进程的计算样式与图片。
