# BYOK 技术方案独立审核

日期：2026-10-09（Asia/Shanghai）。审核对象：`docs/reviews/166-byok-plan.md`，对照 164 调研与 165 调研审核。结论：**通过技术方案阶段审核**。初审发现的预算与非流式输出授权边界已补充并完成复审，可进入测试用例阶段。

## 审核依据

独立阅读 166 及必要已知源文件：`desktop/main/model-configuration.ts`、`desktop/main/model-provider-adapters.ts`、`desktop/main/model-repository.ts`、`desktop/core/model-authorization.ts`、`src/lib/ai/provider.ts`、`src/lib/ai/tool-compatible-model.ts`、`src/lib/ai/timeouts.ts`、`src/components/desktop/ModelConfigurationDialog.tsx`。核对 `package.json` 与安装的 AI SDK v7 `simulate-streaming-middleware.ts` 源码。

官方 SDK 文档确认该中间件用一次非流式生成转换为现有流式接口，并保留文本、思考、工具调用、usage 和元数据。安装源码与此契约一致。[AI SDK 官方文档](https://ai-sdk.dev/docs/reference/ai-sdk-core/simulate-streaming-middleware)

审核未使用、复制或保存用户 Key；未发起认证/生成请求；未实现代码或执行测试。方案审核证明设计可进入下一阶段，不证明功能或模型已通过真实验收。

## 初审问题与复审处置

### P1：响应读完后的模拟流仍需检查取消与授权

安装的 `simulateStreamingMiddleware` 在 `doGenerate()` 完成后，将完整结果入队并关闭流，本身不检查取消或保存配置的授权版本。原方案只描述等待和读取中的取消，无法明确覆盖“HTTP 响应已读完、结果尚未消费”的窗口。

复审确认方案已增加 `highWaterMark: 0` 的按需读取外层 guard，读取前后检查 AbortSignal，并通过主进程 `model.assert` 核对 `snapshot.authRevision`；明确取消、禁用、删除、换 Key 后不得再输出文本或工具事件。所需 main/service/worker 只读断言已加入实施文件边界。**此问题在方案阶段已关闭。** 用例必须分别覆盖非流式等待中和完成后未消费这两个窗口，代码审核还需确认失败时没有事件泄漏或工具执行。

### P2：固定输出预算与付费重试规则缺少可测试数值

原方案使用“可覆盖思考的固定总输出预算”，未明确固定数值、低容量模型裁剪或未知自定义模型默认值。

复审确认预算已写为 2048，已知较小上限取 `min(maxOutputTokens, 2048)`，未知自定义容量取 1024；预算包括思考，采用官方允许的最低 effort 或关闭思考；截断独立报告，不能因部分输出判断成功。真实 runner 串行，每型号的配置短测与生产 SDK 两个验证阶段各一次、`maxRetries: 0`，不自动重试付费失败。两个明确阶段分别验证配置接口和实际生成，不属于失败后的重试。**此问题在方案阶段已关闭。** 用例应验证请求字段与数值，而不能只验证配置常量。

### 新证据澄清：订阅预期拒绝不计为模型可用

主代理补充 MiniMax 常规 API Key 的 M3 初检成功与 Preview 权限拒绝后，审核要求明确官网完整目录和当前凭据可用清单的区别。复审确认 166 已规定：普通 Key 未列出的订阅限定候选不可选；Key 前缀只作官方订阅分组，不推断实际授权；目录与真实拒绝分别记录。验收门槛明确预期拒绝只证明权限用例，不能充当模型可用成功，也不删除官网限定型号来规避完整性。**此澄清在方案阶段已关闭。** 新凭据初检仍不能代替完整逐型号验收。

### 补充确认：端点支持必须包含工具能力

GPT-6.1 Sol 官方明确 Chat Completions 只支持无工具调用，工具调用应使用 Responses。复审确认该精确型号已加入 Responses 路由，避免普通无工具短测成功后，真实 Agent 写作仍降级或失败。[OpenAI 官方型号页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

GPT-5.5 Pro 的非流式与长耗时约束由 165 提出，166 已采用非流式网络请求、真实结果转换、有界短测超时和现有可配置工作流响应超时。[OpenAI 官方型号页](https://developers.openai.com/api/docs/models/gpt-5.5-pro)

## 下一阶段必须追踪的验证

- 六家逐型号清单必须覆盖官网候选与实时目录合并后的范围，记录不被 Key 列出的候选结果；其余六家的官网/契约核对不能写成真实接口通过。
- Responses 的实际 SDK 路径需验证文本、思考、工具调用、finishReason、usage，以及一次网络生成；Sol 的工具路径不能退回不支持工具的 Chat。
- 非流式结果已生成但尚未消费时，取消、换 Key、禁用、删除必须阻止后续事件与工具执行；主进程授权断言应校验版本及当前可用状态。
- 预算必须按各供应商真实请求字段实施；长度截断、HTTP 200 业务错误、认证失败、额度和限流需分别验证，原始错误或回显 Key 不得进入输出证据。
- 旧官方地址与自定义地址仍保持原保存授权范围，发现/测试不会隐式保存；真实 Key 禁止进入原生截图和保存用例。

以上属于实现与验收要求，均已由当前方案承接；本阶段无剩余阻塞问题。
