# 新手引导产品设计

日期：2026-10-11（Asia/Shanghai）。版本：v3，用户已批准。依据：[调研](2026-10-11-onboarding-research.md)、当前用户目标、AGENTS.md 及 docs/implementation-boundaries.md。本轮只做相关测试，不运行全量回归。此前修订移除弹窗内步骤条和冗余说明，放大主题选择区，供应商国产优先、DeepSeek 居文本首位。v3 将主题、资料、文本及文生图模型提交统一为“继续”，最后一页由配置摘要改为“欢迎使用”。

## 进入规则

引导归属本机应用数据目录，不按作品、账号、窗口或进程重置。主题、用户资料与模型本来就是该目录的全局配置；正常迁移随目录保留引导状态。完成记录不进入用户可导出的偏好设置，避免导入配置意外改变本机引导是否完成。

| 条件 | 行为 |
| --- | --- |
| 本地初始化成功，引导记录缺失 | 自动打开完整流程的主题对话框；已有配置回填，不清空。已有安装第一次使用新增引导功能也适用 |
| 完整引导未完成 | 启动时继续最近未确认步骤；已确认的模型用其 ID 回填，避免重复添加 |
| 完整引导已完成，TEXT 记录为零 | 启动时显示“配置文本模型”短入口，可选“开始配置”或“暂不配置”；每会话只提示一次 |
| 用户在模型设置的文本空态点击“开始模型引导” | 直接进入文本 → 文生图 → 完成，不重复主题与用户资料 |
| AI 调用返回没有文本模型，用户点击“去配置模型” | TEXT 记录为零时进入短流程；本次任务不自动发送 |
| 只有 IMAGE 记录 | 仍视为没有文本模型，可走短流程；已有图片配置保持 |
| 有 TEXT 记录但全停用、缺 Key、默认未选或当前任务选择失效 | 沿用对应模型错误与修复流程，不能用“未配置任何文本模型”替代准确原因 |
| 启动失败、迁移维护、writer lease 待处理、关闭或待恢复草稿对话框 | 这些流程优先；解决后才打开/恢复引导，不叠加抢焦点 |

引导打开时，普通设置、模板管理和重复缺模型提示不再叠到其上方；引导结束/退出后恢复入口。真实应用窗控继续可用，不画假的可点击窗控。

## 完整流程

完整流程为“主题 → 用户信息 → 文本模型 → 文生图 → 欢迎使用”，短流程为“文本模型 → 文生图 → 欢迎使用”。弹窗内不显示步骤条或流程编号，以当前标题说明所处页面；文生图询问和编辑仍属同一可选环节。查看器外部的审核控件和流程索引仅供审核，不进入产品。

| 步骤 | 内容与操作 | 确认结果 |
| --- | --- | --- |
| 1 选择主题 | 新独立对话框；宣纸、玄墨、跟随系统三张放大的无文字工作区缩略图；卡片标题与描述置于图外；当前主题默认选中；主按钮“继续”；下方不显示修改入口说明、主题已应用提示或装饰文案 | 选择即时持久化、即时更新实际主题；等待最新写入成功才进入资料；跟随系统保存 system，而非当下解析色；保存异常时仍显示实际错误 |
| 2 填写用户信息 | 复用资料编辑；笔名必填，头像与邮件可选；默认笔名“作者”可直接使用；“返回”“继续”，右上可暂时退出 | “继续”手动提交真实资料及头像草稿，提交成功再进入文本；普通设置中的编辑按钮仍是“保存” |
| 3 配置文本模型 | 复用单模型编辑；供应商、API Key、可用模型；自定义供应商显示原有扩展字段；“返回”“测试连接”“继续”；不显示独立默认用途提示框 | “继续”校验后，同一确认完成模型保存、默认文本 ID、默认审核 ID 和步骤前进；不更改默认模式/兼容的思考强度，不调用生成接口 |
| 4a 要配置文生图模型吗 | 展示横向“仙侠角色＋场景”拼贴图，配简短介绍“可用于封面、角色或场景图片”；“返回”“跳过”“配置文生图模型”；说明以后可在设置添加 | 接受进入 4b；跳过完成引导，保留此前已有图片默认配置，不创建模型 |
| 4b 配置文生图模型 | 复用 IMAGE 单模型编辑；“返回”“跳过”“测试连接”“继续”；不显示独立默认用途提示框 | “继续”原子保存模型、默认文生图 ID 与完成记录；跳过丢弃当前未保存草稿、保留已有图片设置，完成引导 |
| 5 欢迎使用 | 居中品牌印记、标题“欢迎使用”、品牌介绍、按已保存笔名称呼的问候及创作邀请；不展示配置摘要清单；唯一主按钮“开始创作” | 完成记录已落盘才展示欢迎页；“开始创作”、关闭或 Escape 均回到真实工作区，不自动创建作品或发起模型调用；重启不再完整引导 |

模型编辑页不显示默认用途提示框，欢迎页也不列模型或配置清单。文本“继续”同时配置默认文本与默认审核模型，图片“继续”配置默认文生图模型。当前任务保留其原有快照，不自动发送、审核或生成图片；实际配置可在现有设置中查看与修改。

供应商按国产在前、国外在后排列，自定义供应商置于最后。文本顺序为 DeepSeek、阿里云 / 通义千问、Moonshot / Kimi、智谱、小米、MiniMax、腾讯云、字节 / 豆包、OpenAI、Anthropic、Google、xAI、自定义供应商。文生图沿用此顺序并只保留支持 IMAGE 的供应商，首项为阿里云 / 通义千问；不添加不支持图片的 DeepSeek。顺序调整不替换已确认的模型或既有凭据。

已有同类型模型时提供“使用已配置模型”的单选入口，另有“配置新模型”。选用既有模型的“继续”只提交默认用途和进度，不复制模型、不读取原 Key。返回已确认的模型步骤时编辑同一 ID；模型在中途被删除则显示准确错误并回到选择/添加，不用列表首项或未经选择的后备替代。确认既有模型仅允许已启用且相应类型的模型。

## 返回、退出与恢复

“返回”只在相邻步骤之间移动：资料回主题、文本回资料、图片询问回文本、图片表单回询问；短流程的文本首步没有返回。已确认资料回填；未确认资料或模型草稿返回时丢弃。图片表单的返回与跳过先取消其目录/测试请求，清理内存 Key。

标题右上的关闭按钮和 Escape 都等价于“暂时退出”。已确认主题、资料和模型保留，未确认表单内容不落盘；完整流程维持未完成状态，下次启动继续，设置中可点“继续新手引导”。短流程退出后当次不再自动提示，仍可主动再次进入。退出不删除已提交配置，也不将文本配置标为跳过成功。

完整流程关闭窗口再打开与以上恢复相同。未提交 Key、头像预览和表单草稿不跨重启保存。欢迎页关闭即进入工作台，无额外确认框。

主题写入、资料保存、模型确认或完成记录写入失败：留在当前页，字段保留，显示脱敏错误与重试途径；不能推进、显示成功或悄悄替换默认模型。提交时禁用重复确认、返回、退出、跳过；完成后解除。目录读取和连接测试允许取消，不以测试成功代替保存成功。已有事务机制需要在技术阶段扩展并独立审核，不能将普通“save-model”随后“update”两次写入作为满足该契约的实现。

写入异常也可能发生在磁盘实际提交之后。重试须先核对权威状态，复用同一提交身份和模型 ID；不重复添加，不把返回错误直接推断为“磁盘从未改变”。这项契约在技术设计与专项失败注入中独立验证。

## UI 与键盘

每步一个居中模态对话框，沿用宣纸/玄墨暖色、印章色主按钮、现有字体、圆角与细边框；标题上方不再放步骤提示。主题对话框宽 800 CSS px，常规宽窗的三张示意图各高 180 CSS px，内部布局线条同步放大；资料、模型与欢迎页宽 560 CSS px，文生图询问扩至 640 CSS px，缺文本模型短入口仍为 520 CSS px。短窗及窄屏按可用空间缩小示意图，正文可滚动，标题与底部按钮保持可见。主题页下方只保留“继续”按钮以及必要的异常反馈，不放重复的正常状态/帮助文案。

主题、资料和模型的“继续”都带前进箭头，模型页放右侧作为唯一主动作；测试为次要操作，保留“可能产生供应商费用”的现有说明。主题卡片有选中边框及勾选，不只依靠颜色；跟随系统缩略图用左右双色，实际效果由系统当前状态决定。缩略图只有抽象布局线条，不出现演示作品、对话或模型名。

欢迎页居中展示 68px 现有品牌印记、28px 标题“欢迎使用”和“玄印写作，陪你把灵感写成作品。”；正文以真实笔名呈现“{笔名}，你好。”，接“从一个灵感、一段文字开始，写出属于你的作品。”。印记随主题切换；笔名按文本转义，长笔名换行并允许正文滚动。底部居中“开始创作”，宽 200px、高至少 42px。短窗缩小印记及间距；不展示模型测试成功、付费权益或虚构作品。

文生图询问页采用宣传展示风格的“角色＋场景”拼贴横幅：左侧仙侠角色，右侧山峦、云海、楼阁、石桥与水面，以斜向拼贴接缝组织画面。素材为 1774 × 887px 静态 PNG [xianxia-character-scene-v2.png](../../design/onboarding/assets/xianxia-character-scene-v2.png)，[提示词与来源](../../design/onboarding/assets/xianxia-character-scene-v2.md)随稿保存。卡片采用上图下文，2:1 图片铺满卡片宽度，随窄窗等比缩小。整张图片是原生按钮，与下方“配置文生图模型”复用同一接受配置动作；点击只进入文生图配置，不自动生成图片、不改变头像。素材本地加载，不声称由用户已配置模型生成；上一版角色肖像保留为历史素材。

图片悬停使用手形光标。画面在约 700ms 内轻微推进（1.035 倍），右侧渐入深青色衬底，延迟约 180ms 开始浮现“配置文生图模型”。按用户最新要求移除移动光带。文字采用系统楷体（KaiTi / STKaiti，衬线字体兜底），常规 22–30px，暖白金色、轻微字距与细金色装饰线，与仙侠画面的玉色和金色接缝呼应。窄窗文案居中，字号自适应为 17–26px。

键盘聚焦显示同样的入口提示及清晰焦点框，原生 Enter/Space 与点击同效；图片按钮参与现有 Tab 循环。悬停动画只用于支持 hover 的精细指针设备，触控可直接点击且底部配置按钮始终可见。用户开启减少动态效果时，聚焦/悬停直接显示文字与衬底，不缩放或位移；保存期间图片按钮与其他操作同步禁用，光标及悬停效果恢复默认。

正式实现使用现有 Dialog 的焦点约束与背景 inert。主题组用 radio 语义和方向键单选；Tab/Shift+Tab 在当前弹窗循环；进入新步骤把焦点移到标题或首个字段；表单无效时聚焦首个错误并用 role=alert 说明。模型字段中的 Enter 不无意发起测试或保存，IME 合成中的 Enter 不提交。完成/退出后焦点返回引导入口；首次自动触发时回到工作台主要入口。

正式窗口遵循原有最小宽度；还应在窗口缩放/系统 DPI 下验证短窗滚动和按钮可达。HTML 查看器支持 360px 窄屏供审核阅读，不把它算成桌面目标系统验证。

## 设计审核稿与后续实施

HTML 入口：[design/onboarding/index.html](../../design/onboarding/index.html)。查看器上方提供独立审核控件：完整/仅模型、步骤查看、主题、异常演示与重置。审核控件不进入正式产品。审核表单不得输入真实资料或 Key；只使用明确的设计占位，值只在当前页面内存，不连接网络、不持久化模型或资料。模型测试只演示脱敏失败，不伪造连通成功。

UI 批准后依次完成技术方案及独立子代理审核、专项测试用例及独立审核、TDD 实现及 code review、相关自动测试和真实 Windows Electron 验证，再出总结。专项范围如下，编号用于后续细化，不代表已执行：

| 编号 | 必须覆盖 |
| --- | --- |
| ONB-01 | 首次、缺标记、已有配置回填、完整流程一次触发 |
| ONB-02 | 三种主题即时保存、跟随系统变化、保存失败不前进 |
| ONB-03 | 资料确认、校验、可选邮箱/头像、返回/退出清理头像草稿 |

用户已批准最终 UI v3，技术和专项测试用例已通过独立审核，产品实现与专项验收据实际证据更新本次台账。HTML 检查只证明设计查看器；不替代产品事务和Windows Electron验证，不改写旧验收状态。

实施审核明确：写后错误且操作与权威receipt匹配时，暂时冻结字段、返回、跳过及测试，“继续”专门确认同一份原提交，收到成功确认才推进；显式退出仍允许。普通写前错误仍可修改字段。连接测试期间可以返回、跳过或退出取消；保存提交期间阻止这些动作。高优先级弹窗暂停头像选择时保留UI已接受的头像草稿，主进程迟到的选择不能覆盖它。
