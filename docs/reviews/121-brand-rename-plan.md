# 玄印写作品牌统一方案

2026-10-08。授权：以用户最新更正为准，项目中文全名为「玄印写作」、简称为「玄印」、英文名保持「XaanInk」，全部旧中文品牌使用改为新名称。

## 实施范围

- 应用标题、加载/错误提示、关于窗口、原生菜单、设置、导出文件名和文档作者元数据统一中文全名；系统菜单及对应隐藏/退出命令用简称。
- npm 项目名采用 `xaanink`，安装包采用 `XaanInk-${version}-${os}-${arch}.${ext}`，安装程序及应用图标名称采用「玄印写作」，bundle ID 采用 `ink.xaanink.desktop`。
- 本地协议、测试环境变量、日志/测试目录前缀及非持久化 IPC 标识统一 `xaanink` / `XAANINK`。
- 修改真实 SVG 字标路径中的旧文字，使用仓库已有、获许可字体生成新字标路径；保留无文字图形标。更新可访问名称、SVG 说明及打包时生成的 PNG/ICNS/ICO。
- 中文文档、设计预览、测试夹具和退役源码同样更新。历史截图不修改伪造；它们属于过去的验证证据，不作为新品牌验收证据。
- 来源仓库、当前 GitHub 地址等真实外部引用保留准确链接；不把链接改成尚不存在的仓库。
- 用户确认「兼容旧版数据，新建数据使用新名称」。旧标识仅作为文件协议兼容值保留；所有可见中文名称与新创建的文件使用新品牌。

## 数据兼容契约

- 用权威应用/作品 marker 选择旧/新命名家族，不改写旧目录，不复制数据库、密钥或尚未完成的维护记录。已存在旧 bootstrap 时继续沿用原 `userData` 和单实例锁；从原 pointer 打开已有根目录。
- 新安装使用 `XaanInk` bootstrap 与 `~/.xaanink`；有效旧默认根继续打开。损坏旧状态必须报错，不得静默初始化空新目录。
- 旧作品继续使用其旧 manifest/storage/lock/audit 家族；新作品采用 `xaanink-*` 与 `.xaanink-*`。同一目录的双 marker、跨家族混合控制记录和未知/存活锁必须拒绝，不能因改名另取新锁。
- 管理文件清单、目录重定位、迁移及导出保护识别两家族；旧 journal 和校验和保持原始字节语义，新操作写入对应目录家族。
- 配置和模板导入接受旧格式与新格式，导出只生成新格式；兼容值不得出现在正常界面的品牌文案中。
- macOS `safeStorage` 的 Keychain service/account 由 Electron 启动时的应用名称生成。旧 bootstrap/旧根须保留启动加密身份，初始化后恢复新显示名，避免已保存模型密钥失效；使用隔离的假凭证做真实跨进程验证，不读取或输出作者模型密钥。[Electron 44.6.0 源码](https://github.com/electron/electron/blob/v44.6.0/shell/browser/electron_browser_main_parts.cc#L636)。旧名称仅允许作为这一兼容值及明确旧格式测试夹具，不作为产品文案。

## 顺序与验证

1. 独立子代理审核本方案。
2. 新增品牌回归测试并更新相关已有断言，独立审核用例，运行并记录改名前失败。
3. 分范围实现并独立代码审核，修复问题后复验。
4. 执行全部活动核心用例、类型检查、生产构建、实际 macOS arm64 应用目录封包及包内资源检查。
5. 运行真实新包，检查窗口标题、菜单、关于及新字标，正常退出/重开。只记录实际执行结果，Windows 保留未执行。

## 边界

不改业务行为、已批准布局、模型配置或备份撤销范围；不访问真实作品或密钥；不创建 HTTP 服务；不修改上游目录。不更改 Git 远程、不发布安装包、不把本次品牌验证声明为全量业务验收。
