# UI v0.11 长字段、主题与卡片独立审核

日期：2026-10-07（Asia/Shanghai）。审核者：独立 UI 子代理。范围：产品 v0.10、补充契约 v0.3（前序 `17-product-settings-layout-review.md` 已通过）、`03-ui-design.md` 第 11 节及本轮原型布局修订。

## 当前结论

**通过本轮 UI 原型独立复审，无阻断项，无待修复 UI 项。** 长字段、主题、模型属性及卡片修订与产品/契约一致，可交用户审核。主代理独占浏览器并执行交互检查；本子代理独立核对源码、文档、本地截图及记录，本轮只计 v0.11 的 24 项原型检查和 11 张截图，不累计历史数量，也不替代用户批准或真实桌面验收。

## 源码与契约核对

- 应用数据目录、默认作品父目录和主题明确添加 `setting-row-stacked`，标题/说明在上，全宽控件在下；路径输入与迁移/选择按钮同行，完整路径 title 保留。短设置、开关与智能体继续左右排列。主题仍为同排三图，纯图形缩略图增高，单选/即时变更逻辑未改。
- 配置模型所有 `.field` 由网格改为纵向 flex，标签、全宽控件和说明依序排布；覆盖供应商、Key、目录、自定义属性及高级上下文。高级容器已单列。该覆盖限定 `.model-dialog`，没有覆盖 `.profile-editor-fields`，用户编辑继续左头像、右属性。
- 模型对话框仍为受窗口高度限制的纵向 flex；只有内容区滚动，底部按钮区不收缩。模型单选、手动保存/取消与直接测试逻辑未改。下拉依旧按配置内容区边界向上/下展开并限制高度，以 fixed 定位及 preventScroll/菜单自身滚动避免短窗祖先滚动误关闭。
- 模型清单仍按文本/文生图分组，行最小高度为常规 86px、窄窗 80px，增加垂直留白；名称/ID省略、Logo、状态及操作保持。组内细线和首末圆角规则保留。
- 用户卡片渐变由语义主色与 card 混色产生，边框/阴影跟随两主题；头像为常规 72px、窄窗 64px。纯铅笔按钮 34px，保留 `aria-label`/title「编辑用户」与非收缩尺寸。长笔名/邮件所在 grow 保留 min-width:0，文本省略且完整 title 经转义；用户资料仍在显式保存后提交。
- 本轮 diff 仅改变相关展示结构及样式，多快捷键集合、模型草稿/测试保护、资料提交和工作台行为未改；不重复与布局无关的全量逻辑检查。

## 本轮证据独立复核

直接读取 `design/evidence/v0.11/checks.json`，24 个 ID 唯一且均为 pass：A01–A06 对应上下路径/主题、短属性及 Windows 窄窗，U01–U06 对应新卡片、Tab/Enter、资料布局和取消、长文本与实际按钮命中，M01–M10 对应增高卡片、预设/自定义全属性、短窗菜单与单选保存、长表单滚动/供应商边界和取消，D01–D02 对应 ID/本地资源/CSP 与控制台。GUI 由主代理执行，子代理没有重复操作或注入浏览器状态。

本轮 11 张截图均独立查看：

- 常规宣纸与 Windows 640 玄墨的通用/外观显示路径和动作同行、主题三图占满下一行；字体等短设置保持左右，内容区滚动，无横向布局溢出。
- `model-config-windows-ink.jpg` 显示预设供应商、Key 和可用模型各自上下全宽；`model-custom-bottom-640.jpg` 显示 640×560 自定义高级上下文和说明完整可达，底部保存模型/测试连接/取消仍可见。完整八项结构另由 M06/M07 的字段度量支持，不把底部截图当作全部字段同屏展示。
- `model-dropdown-640.jpg` 显示全宽目录向上展开及末项整行；搜索保持展开和单选提交由 M03–M05 支持。长表单滚回顶部的供应商菜单边界由 M08 记录与未改的定位源码共同支持。

本子代理执行本轮修改的 `desktop-preview.js` 的 `node --check` 和 `git diff --check`，均通过；最终源码 diff 未增加相关交易/快捷键逻辑变化，无需重复多绑定逻辑测试。没有本轮发现的阻断或修复事项。最终 SHA-256 清单由主代理在审核定稿和状态文案更新后生成，交付前再只读核对；本审核不声称已验证尚未生成的清单。

## 阶段边界

该轮只审核浏览器内存 UI 原型。没有真实 Electron/macOS/Windows 原生窗口、磁盘持久化、供应商目录/网络请求或安装包验收。用户仍须明确批准 UI，之后再依原顺序进入技术方案、最终测试用例、TDD 实现与真实桌面验收。
