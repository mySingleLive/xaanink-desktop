## 目录承诺与凭据边界

目录承诺目前诚实：安装版要求所选端点与 Key 范围下完整匹配类别目录、全部分页及权限/网络/认证失败状态，明确公开目录不等于授权全集，没有授权发现时保留“权限待验证”且逐项验证后才称可用。单次连接测试不能证明全部目录可用，刷新不能删除旧记录。调研显式承认逐供应商发现能力尚未核验，不能以同一 GET /models 假设、精选型号、第一分页或静态示例充当完成。

原型目录使用 demo ID/示例名称，CSP 禁止模型联网，不包含真实型号/能力完整性保证。此阶段允许审查布局和交互；“全可用目录已实现”“供应商兼容已验收”或“App 测试已通过”均不能由这些材料得出。正式技术阶段须逐供应商核验完整发现和授权判断，并将无法满足的范围显式报告，不可静默降低用户要求。

独立草稿与撤销时点已得到主要澄清：未保存 Key 仅在临时草稿，可经显式费用确认测试；草稿改授权端点清空草稿 Key，取消不损坏旧模型；成功提交授权变更，或显式删除/禁用/清除 Key，取消旧请求并阻断后续/重试，保留候选与对话草稿。测试结果绑定单个草稿型号，换草稿/取消使迟到结果失效。Key 轮换的最后歧义见 PRD-MA02。

## 审核与继续边界

当前仅为 UI 阶段，用户尚未批准。即使产品修复通过，也只允许继续 UI 独立审核和用户审核，不代表技术、代码、全目录发现、本地持久化、真实 Electron 两平台验收或完整功能迁移已经开始或完成。旧产品与 UI 审核记录不被此次结论覆盖。

## 定向复核

2026-10-07 重读能力矩阵及产品/UI 的授权条款：新增智能体已使用唯一 D09，既有独立安装 D08 保留，末尾声明同步；PRD-MA01 关闭。产品与 UI 现已明确同供应商/端点更换 Key 也在成功保存时增加授权版本、撤销旧授权并取消旧请求，后续调用不沿用旧 Key；草稿取消或保存失败不改旧记录，目录及模型可用性仍须按新 Key 权限判断。最终仅定向复核 `provider-ui-presets.md` 第 21 行：已同步同端点 Key 替换、授权版本和“新 Key 不沿用旧权限验证状态”，预设一致性建议也已关闭，PRD-MA02 无遗留项；没有重审全文或运行真实接口。

**最终结论：产品 v0.5 修订通过，无阻断项。** 真实全目录/授权发现及能力判断仍待技术阶段逐供应商核验，不能据此审核声称已实现或 App 验收通过。UI 用户批准门仍然有效。
