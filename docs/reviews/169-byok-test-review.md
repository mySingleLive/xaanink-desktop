# BYOK 测试用例独立审核

日期：2026-10-09（Asia/Shanghai）。审核对象：`docs/reviews/168-byok-test-cases.md`，对照 164—167 调研、方案及独立审核。结论：**通过测试用例设计阶段审核**。B01—B29 共 29 条设计已覆盖当前方案，可进入先失败回归、再实现的 TDD 阶段。本阶段未执行测试，不填写测试通过。

## 审核方法

逐项核对用例前置、操作、预期、执行层级和证据入口；依据前两阶段已核对的生产配置服务、Key 仓库、HTTP 授权网关、实际 SDK 工厂和非流式中间件契约进行独立检查。只读检查相关测试与原生脚本文件名，确认 `model-configuration`、`model-service`、`model-settings`、`local-model-generation`、图片生成测试，以及 `scripts/smoke-models.mjs`、`scripts/smoke-electron.mjs` 的既有入口存在。

新增 BYOK 回归、SDK 集成及 `verify-byok` runner 是下一阶段需实现的入口；其存在或预期不能在本阶段作为执行成功证据。审核未认证请求、未使用或保存真实 Key、未实现代码；只写本审核文档。

## 已关闭的澄清项

- **B01 保存授权复用**：已明确新配置无 Key 不可发现；编辑已有同范围有效授权时可以留空复用。不会将空输入错误解释为删除或拒绝使用已保存 Key。
- **B10 错误预期**：已明确认证、权限、额度、限流、型号不可用的固定码及 HTTP 200 业务错误处理。服务端回显 Key 是独立负例；返回内容必须脱敏，不允许因 HTTP 200 或存在部分输出判断成功。
- **B14 截断字段**：已明确 Chat `finish_reason: length`、Messages `stop_reason: max_tokens`、Responses `status: incomplete` 与 `reason: max_output_tokens` 的预期为 `OUTPUT_TRUNCATED`，并断言无第二次 POST。
- **B24 图片阶段与费用次数**：已明确配置短测和生产图像生成两个阶段各一次、每次一张；配置阶段验证响应契约，生产阶段承担真实下载/内联解码证明，不能用格式正确的 URL 代替图片成功。
- **B27 真实负例**：明确使用自定义 OpenAI 与官方 OpenAI 端点，固定无效测试 Key 得到 401/认证失败；有效 Key 请求固定不存在型号得到 404/型号不可用。记录只含固定脱敏结果，不保留请求头、原始错误或真实 Key。
- **B28 可执行入口**：已改用存在的 `smoke-electron` 及明确离线启动检查，避免引用不存在的 `smoke-offline` 脚本作为执行证据。

## 可执行性与证据要求

1. U/I 的受控响应只证明接口契约或实际 SDK 集成；N 只证明隔离 Electron UI；六家调用可用性必须由 R 的逐型号结果支持。用例文档已作此区分。
2. B22—B25 必须完成整批内置执行后再开始 B26。证据应含供应商、型号、阶段、时间及成功/失败/未执行，保留官网候选全集和当前凭据选用状态，不能仅写一个供应商启动成功。
3. 两阶段各一次与失败后的重试分别记录。明确修复后重测可执行，但旧失败结果须保留并说明修复，不能用后一次成功覆盖历史失败或隐藏付费请求次数。
4. B18—B20 必须消费真实 SDK 事件并校验文本、思考、工具、finishReason、usage、网络生成次数；完成后窗口用例必须在读取模拟流之前使取消/授权失效成立，避免测试只覆盖 HTTP 仍在进行的情况。
5. 图片证据应保存脱敏的实际解码布尔值、格式、数值维度及对应阶段；签名下载 URL、图片正文、原始响应和请求凭据不进入证据。B15 还应确保外部资源读取不携带 API Key。
6. B10/B27 错误用例应构造正确协议字段，验证返回固定码和无敏感内容；业务错误不能只通过宽泛消息文字匹配制造成功。B29 必须检查整个证据输出，而不只检查单个成功对象。
7. 最终验证文档必须将每个 B 编号落到具体命令、测试文件和结果。新增测试失败应先留 TDD 证据，代码独立审核关闭问题后再执行完整验收。

当前无剩余用例设计阻塞项。全部必需正例、预期拒绝负例、回归和真实目标系统证据完成后，才可给出最终验收通过结论。
