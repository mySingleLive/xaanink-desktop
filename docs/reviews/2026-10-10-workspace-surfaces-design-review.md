# 工作区分割线与宣纸底色设计审核

日期：2026-10-10。第三版。审核方式：独立子代理只读检查，主代理记录返回意见。结论：第三版调研及设计预览核对通过，无剩余必须修正项；用户已明确回复“UI 审核通过，继续”。前两版审核已归档，不作为本版结论。

## 审核对象

审核覆盖更新后的调研、第三版设计说明、前后对比 HTML、预览采集脚本、计算样式 JSON、查看器检查 JSON、当前及 `proposed-v3.png`、`review-viewer-v3.png`。子代理独立读取源码、核对 Git 状态、相关源文件及截图哈希，并查看实际图片。

## 结论与证据

- `DashboardShell` 左分隔条默认透明而右侧存在 `withLine`。未选择会话仍使用 `.chatpane`。调研准确区分了截图现象与源码原因。
- 左 `#f5eedc`、中间 `#faf6e8`、右 `#f8f3e4`，三栏整体提浅，保留两侧略深、中间略浅。AI 与右侧 RGB 差只有 `(2,3,4)`，小于 AI 与导航的 `(5,8,12)`，与最新要求一致。AI 元素层 `#fcf8ee` 保留略浅的层次。
- 两条分隔元素仅边框占位，无子线或实色底条，颜色调浅为 `#d8cba6`。当前 Electron 44.6.0、zoom 1、DPR 1.5 下，声明 1px 边框使用宽度约 `0.666667` CSS px，与 AI 顶栏及账户横线相等，对应 1 个设备像素。前版实色条的名义 1px 宽度不等于这个边框的实际使用宽度，第三版已统一绘制方式。
- 计算几何显示面板与线直接相接。原始 PNG 像素核对中，左竖线为 x=631、右竖线为 x=1397 的单列，AI 顶栏为 y=65 的单行；相邻像素回到面板纸色，无附加亮色沟槽。
- 右规划使用专用内容底色 token 与原变量 fallback；右 Monaco 拟局部覆盖正文和行号槽变量。方案保留原组件，不全局覆写 `--background`、`--border` 或 Monaco 主题，符合实施边界。空态预览脚本没有全局覆写这些变量。
- 普通 Separator、菜单和 Markdown hr 的实色条纳入后续统一边框的实施范围。文档及采集 scope 均明确这些元素未在空态实例化，本次不宣称这些状态已验证。
- 预览脚本使用新隔离目录、零配置模型、宣纸主题和真实 `xaanink://app` 工作台。修改仅临时注入预览进程，Git 状态中没有产品源码改动。三个相关源文件及两 PNG 的 SHA256 均经独立复算，与 observations 一致；脚本 `node --check` 通过。此前共同 inspect 中的 authored 声明字段已移除，第三版声明置于根 `proposedDividerDeclaration`，不再误用于当前界面。
- 主代理用 Chrome 核对第三版 HTML 对比稿：1440px 与 360px 下图片加载及前后切换正常，没有横向溢出或脚本错误。`viewer-checks.json` 的 revision 为 v3，scope 明确是设计查看器检查，独立子代理另核对了查看器截图及记录的一致性。

## 证据范围

上述结果是设计及设计查看器核对，不属于产品回归通过，也不属于原生窗控或跨平台验收。源码哈希说明采集记录对应的源文件未变，不能单独证明运行 bundle 与源码的完整对应关系；实际底色、线宽和邻接结论来自预览进程的计算样式、几何及图片。

空态画面未运行菜单、标签条、业务及 Markdown 分割线、其他缩放、右侧规划、Monaco 正文或实际拖拽命中，不能证明这些项目已通过；调研、设计及采集 scope 均明确此限制。分栏库默认不可见命中区与 Monaco 局部变量方案有源码依据，实际交互仍留待实施验证。后续实现与验收须按用户指定顺序及仓库技术、用例、TDD、code review、真实系统要求执行。
