## 内嵌数据库与 Prisma 可行性

PGlite 官方支持 Node 本地文件存储、参数查询及回调事务；Prisma v7 官方列有社区 PGlite 驱动适配器，也允许自定义 adapter。因此采用进程内 PostgreSQL WASM 保留原数组、枚举、JSON 和事务规则的方向成立，无需数据库 daemon、socket 或本地 HTTP 服务。这是可行性判断，仍需锁定版本的实际契约验证。[PGlite 文件系统](https://pglite.dev/docs/filesystems)、[PGlite API](https://pglite.dev/docs/api)、[Prisma 驱动适配器](https://www.prisma.io/docs/orm/v7/core-concepts/supported-databases/database-drivers)。

官方明确 PGlite 是单独占连接，支持 TD01 的调度要求。[PGlite 入门文档](https://pglite.dev/docs/)。社区源码可见 `executeScript` 未等待执行、隔离级别设置位于事务前、事务错误转交外层已解决 Promise 的风险。技术稿选择锁定社区版本只复用类型/参数/错误转换，本地 wrapper 覆盖脚本及事务层，符合本次审核意见。wrapper 必须等待引擎真实结束并传播错误，而不能以 deferred 已解决推断提交成功。[社区适配器源码](https://github.com/lucasthevenet/pglite-utils/blob/main/packages/prisma-adapter/src/pglite.ts)。

保留原 CAS、幂等回执、正文版本快照、候选/作者批准/定稿、评论锚点和聊天 lease/write fence 的方案明确；不可通过删锁 SQL 或降低校验绕过兼容问题。正式测试用例审核后，应先以 RED 契约证明类型转换、脚本失败、提交失败、取消/超时回滚、事务外读写排队和嵌套 tx 边界，再扩展业务迁移。适配器失败阻断后续里程碑，不能回退平台数据库。

## 本地数据、IPC 与模型边界

- 每作品显式目录与 UUID、opaque 目录授权、受信 catalog 解析 DB context、请求/任务固定上下文及 LRU/锁规则，避免切换当前作品导致串库。inbox 转移日志、作者/模型本库关系和失败权威库规则已定义。
- 应用根迁移使用暂停、落盘、allowlist、校验、原子权威指针与可恢复日志；旧根只清理所有权及散列匹配文件。作品目录不随应用根迁移。备份及恢复隔离候选库，不直接复制活跃库；未知文件、原正文及当前恢复点得到保留。
- renderer 无 Node/fs/任意 SQL 能力，IPC 验证当前受信主 frame、schema、大小和作品授权；协议资源限制根路径及 symlink，图片按 manifest ID 查询。流的请求/作品/会话/attempt 标识、序号、背压、取消、迟到丢弃与写入 fence 一致。
- 全部 AI 分支使用统一授权解析和最后网络出口，审核/文本/图像路由分离；已有空选或失效模型不自动补位。模型目录区分官方完整目录、授权发现及待验证权限，不以设计演示目录作真实授权证明。原平台套餐、余额、Auto/Kimi 改路由与平台后备明确移除。
- 原生窗口/菜单、设置实时回执、模型/用户手动草稿、多快捷键及 Monaco 焦点/IME 通过原组件与统一命令源接入；Next 静态资源全部本地打包，不要求用户部署服务。

以上为技术契约通过。跨作品伪造、取消/撤销迟到、导入凭据隔离、断电/保存失败/迁移恢复、禁远端平台与无监听端口，都必须在下一阶段映射为可验证用例，不得由架构图代替证据。
